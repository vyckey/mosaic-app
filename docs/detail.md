# 拼图 (Mosaic) - 产品细节

> 本文件从 [memory-product-design.md](memory-product-design.md) 中拆分而来，包含第四部分「产品细节」的完整内容。

## 产品细节

### 1 APP 信息架构

#### 1.1 底部 Tab 结构

```
┌─────────────────────────────────────────┐
│                                         │
│              [页面内容区]                 │
│                                         │
├────────┬────────┬──────┬────────┬───────┤
│  今天   │ 时间线  │  ＋  │  对话  │  我   │
└────────┴────────┴──────┴────────┴───────┘
```

| Tab | 定位 | 承载内容 | 用户心声 |
|-----|------|---------|---------|
| **今天** | 每日 Hub | 今日碎片 + 那年今日 + 每日一问 + AI 洞察 | "打开看看今天的我" |
| **时间线** | 回忆浏览 | 全部历史记录，多视图（时间流/日历/地图/分类），搜索 | "翻翻过去的我" |
| **＋（记录）** | 核心动作 | 中心突出按钮，点击弹出记录面板，不是独立页面 | "记下这一刻" |
| **对话** | AI 交互 | 统一 AI 对话，既能查询数据也能探索自我，包含话题引导 | "和自己的数据聊聊" |
| **我** | 自我画像 | 我的画像 + 关系画像 + 仪表盘 + 人生故事 + 设置 | "看见完整的我" |

**设计理由**：

- **记录是中心 FAB，不是 Tab 页面**：记录是一个"动作"，不是一个"页面"。用户从任何 Tab 都能一键发起记录，完成后回到原页面。
- **对话 Tab 统一了 AI 对话记忆（3.3）和认识自己的对话功能（3.4）**：两者的交互形式都是对话，拆成两个 Tab 会让用户困惑"我该去哪里问？"。统一后，用户在一个地方既能问"上次吃火锅是什么时候"，也能聊"我是一个什么样的人"。
- **"我" Tab 承载认识自己的非对话部分**：画像、仪表盘、人生故事、探索话题卡片都在这里。它是"看见自己全貌"的入口，不是对话。
- **那年今日嵌入"今天" Tab**：它是每天打开 APP 的惊喜，属于首屏体验，不需要独立 Tab。

**常驻输入条**（仅"今天" Tab）：

固定在页面底部（Tab 栏上方），不随页面滚动。用户无需点开任何按钮就能看到记录入口。

- 点击输入条文字区域 → 展开为完整记录面板
- 直接点 😊 → 弹出心情 Emoji 选择，一秒完成心情打卡，不需要展开面板
- 直接点 📷 → 打开相机，拍完后自动带入记录面板
- 直接点 🎤 → 立即开始录音，说完自动转文字进入记录面板
- 其他 Tab 下仍然通过中心 ＋ 按钮发起记录

**首屏内容优先级**（从上到下）：

| 优先级 | 内容 | 条件 | 作用 |
|--------|------|------|------|
| 1 | 那年今日 | 有历史记录时显示 | 情感驱动，让用户感受到记录的价值 |
| 2 | 今天的碎片 | 今天有记录时显示 | 成就感，"今天已经留下了 3 块拼图" |
| 3 | 每日一问 | 今天未回答时显示 | 降低记录门槛，引导输入 |
| 4 | AI 洞察 | AI 发现有价值的规律时显示 | 惊喜感，"原来我是这样的" |

**设计原则**：

- **有内容感**：首屏永远不是空白的——即使是新用户，也有欢迎卡片、导入引导和每日一问

- **记录入口随时可达**：常驻输入条始终可见，点 😊 一秒打卡，点输入条展开完整面板
- **信息密度适中**：每个卡片独立，可滑动浏览，不堆砌

### 2 记录体验

#### 2.1 记录入口

记录有两个入口：
- **"今天" Tab 的常驻输入条**：最高频入口，无需点开任何按钮
- **其他 Tab 的中心 ＋ 按钮**：保证在任何页面都能发起记录

两者点击后都展开同一个记录面板。

**记录面板（半屏弹出）**：

```
┌──────────────────────────────────────┐
│                              [✕ 关闭]│
│                                      │
│  📷  🎤  📍  🏷️  📝  ← 记录方式    │
│  拍照 语音 位置 标签  日记             │
│                                      │
│  😊 😢 😡 😴 🤔  ← 快捷心情         │
│                                      │
│  ┌──────────────────────────────┐    │
│  │ 记下点什么...                 │    │
│  └──────────────────────────────┘    │
│                                      │
│  AI 识别：[运动记录 ▼]  ← 实时分类    │
│                                      │
│  [记下]                              │
└──────────────────────────────────────┘
```

**布局逻辑**：图标在最上面，输入框在下面。用户打开面板第一眼看到的是"我可以拍照、录音、定位"——不想打字的人直接选择其他方式，想打字的人往下看就是输入框。

**分层记录——从 1 秒到 10 分钟**：

记录面板不是一个固定界面，而是按深度自然分层，用户可以在任何一层停下来：

| 层级 | 操作 | 耗时 | 示例 |
|------|------|------|------|
| Layer 0 | 在输入条直接点 😊 | 1 秒 | 心情打卡，自动附加时间/位置/天气 |
| Layer 1 | 输入一句话 + 可选 emoji/照片 | 5-10 秒 | "今天跑了5公里" |
| Layer 2 | 展开面板，AI 分类 + 标签 + 定位 + 多张照片 | 30-60 秒 | 完整的旅行记录 |
| Layer 3 | 点击 📝 进入全屏日记编辑器 | 5-10 分钟 | 长篇日记/手记 |

**交互规则**：

- 点击 📷 → 打开相机/相册，选完后照片出现在输入框上方，可继续添加文字描述
- 点击 🎤 → 立即开始录音，说完自动转文字填入输入框，用户可编辑
- 点击 📍 → 手动选择位置（默认自动获取当前位置）
- 点击 🏷️ → 手动添加标签（AI 也会自动建议标签）
- 点击 📝 → 展开为全屏日记编辑器（自动切换到富文本模式）
- 心情 Emoji 为可选项，点击即附加到记录中，可以只点 Emoji 不写文字
- 输入文字后，底部实时显示 AI 识别的类型标签（如"运动记录"），用户可点击修改
- 按钮文案是"记下"而非"发布"——这是写给自己的，不是发给别人看的
- 用户修正 AI 分类后，AI 从修正中学习，越用越准

#### 2.2 日记编辑器

当用户选择写日记或内容较长时，自动切换到富文本编辑模式：

- 使用所见即所得编辑器（基于 Tiptap）
- 支持标题、加粗、列表、引用、插入图片等基础排版
- 存储格式为 Markdown（轻量、可导出、不绑定框架）
- 同时提取纯文本版本用于搜索和 AI 分析
- 支持草稿自动保存，可多次编辑

#### 2.3 结构化模板

提供预设模板降低"不知道写什么"的心理负担：

**每日三问**
```
今天最开心的事：___________
今天学到了什么：___________
明天想做的事：_____________
```

**运动打卡**
```
运动类型：[跑步 ▼]
时长：____ 分钟
距离：____ 公里
感受：😊😐😫
备注：___________
```

**旅行日记**
```
📍 地点：___________
🌤️ 天气：___________
💰 今日花费：_______
⭐ 今日最佳：_______
📸 [添加照片]
📝 今日见闻：_______
```

- 支持用户自建模板
- 后续可开放模板市场，用户之间分享模板

#### 2.4 自动上下文捕获

每条记录自动附加当时的环境信息，用户无需手动输入：

```
📍 位置：北京市朝阳区 三里屯
🌡️ 天气：晴 32°C
🎵 正在听：周杰伦 - 晴天
🚶 今日步数：8,432 步
💤 昨晚睡眠：7h 12m
```

这些上下文在回顾时能强烈唤起记忆（"哦对，那天在三里屯，还在听晴天"）。

#### 2.5 每日一问

每天晚上定时推送一个问题，引导用户完成一次记录：

```
今天最开心的一件事是什么？
今天学到了什么新东西？
今天最感谢谁？
如果今天能重来，你会改变什么？
用三个词形容今天。
此刻你在想什么？
```

- 用户只需要回答一句话，就完成了一次记录
- 不是让用户"写日记"，而是让用户"回答一个问题"，心理门槛完全不同
- 推送时间可自定义（默认 21:00）
- 可以跳过，不产生任何负担

#### 2.6 智能提醒

基于场景触发记录提醒，而不是定时打扰：

| 触发条件 | 提醒内容 |
|---------|---------|
| 到达新城市 | "到新地方了，记录一下？" |
| 今天拍了很多照片 | "今天拍了 15 张照片，要整理成记忆吗？" |
| 运动结束（接入健康数据） | "刚跑完步，感觉怎么样？" |
| 连续多天没记录 | "最近在忙什么？随便写一句也好" |
| 特殊日期 | "今天是你和小明认识的第 1000 天" |

**数据如何映射到 MBTI 四维度**：

| 维度 | 数据来源 |
|------|---------|
| E / I（能量来源） | 社交频率、1v1 vs 群体偏好、社交后情绪变化、独处记录的深度 |
| S / N（信息获取） | 阅读偏好类型、记录中抽象 vs 具体词汇比例、关注细节 vs 宏观的模式 |
| T / F（决策方式） | 决策记录中的理性 vs 感性倾向、情感表达频率、复盘风格 |
| J / P（生活方式） | 作息规律性、目标追踪行为、计划性 vs 随性的记录模式 |

**设计原则**：

| 原则 | 说明 |
|------|------|
| 连续谱，非标签 | 每个维度显示百分比而非二元标签，"你是 78% 的 I"比"你是 I"更准确 |
| 数据透明 | 每个维度都列出具体的数据依据，用户可以判断是否准确 |
| 场景感知 | 不同场景下的人格漂移是特色功能——展示"多面的你" |
| 时间动态 | 追踪 MBTI 随时间的变化，发现人格成长的轨迹 |
| 不神化 | 明确说明这是数据推导的参考，不是心理诊断 |
| 可校准 | 用户可以输入问卷结果对比，两者的差异本身就是有趣的自我认知 |

| 时间范围 | 支持多粒度切换，看短期波动也能看长期趋势 |

#### 4.6 趋势预警

趋势预警不是独立页面，而是出现在三个位置：

**位置一："今天" Tab 首屏卡片**

当 AI 检测到需要关注的趋势时，以卡片形式出现在首屏：

```
┌──────────────────────────────────────┐
│  ⚡ 趋势提醒                          │
│                                      │
│  你已经连续 7 天没有运动了             │
│  之前最长中断是 5 天                  │
│                                      │
│  [去记录一次运动] [知道了]             │
└──────────────────────────────────────┘
```

**位置二：各维度画像详情页顶部**

进入某个维度画像时，如果该维度有异常趋势，顶部显示预警条：

```
┌──────────────────────────────────────┐
│  ⚠️ 你最近 5 天的情绪评分连续下降      │
│  从 8.2 → 7.5 → 6.8 → 5.9 → 5.2    │
│  [和 AI 聊聊]               [忽略]   │
└──────────────────────────────────────┘
```

**位置三：推送通知**

特别值得关注的趋势，通过系统推送提醒：

```
拼图：你已经连续 7 天没有运动了，之前最长中断是 5 天。
     要不要记录一下最近在忙什么？
```

**预警类型**：

| 类型 | 触发条件 | 语气 |
|------|---------|------|
| 中断预警 | 某个习惯中断超过历史最长记录 | 温和提醒，不施压 |
| 下行趋势 | 某指标连续 3-5 天持续下降 | 关心，不说教 |
| 正向里程碑 | 某指标创新高或达成阶段目标 | 庆祝，强化正反馈 |
| 异常波动 | 某指标突然大幅偏离基线 | 好奇式询问 |

**正向里程碑示例**：

```
┌──────────────────────────────────────┐
│  🎉 新纪录！                          │
│                                      │
│  你本月阅读量已经超过上月全月了！       │
│  继续保持的话，这会是你今年            │
│  阅读最多的一个月。                    │
│                                      │
│  [太棒了]                             │
└──────────────────────────────────────┘
```

**预警设计原则**：

- **不说教**：用数据客观陈述事实，不下结论、不给建议，让用户自己判断
- **不焦虑**：预警频率控制，不是每天都弹，只在真正值得关注时出现
- **可关闭**：用户可以对某类预警选择"不再提醒"
- **正负兼顾**：不只提醒坏消息，正向里程碑同样推送，保持产品的温暖感

### 5 分享机制

拼图不做社交网络，但支持三种轻量级的分享方式：

#### 5.1 分享卡片

用户选择一条记录，生成精美的分享卡片，可分享到微信、Instagram 等外部平台：

```
┌──────────────────────────┐
│  📅 2026.08.30           │
│                          │
│  周末爬了香山，           │
│  秋天的颜色太美了。       │
│                          │
│  [照片]                  │
│                          │
│  ── 来自拼图 ──           │
└──────────────────────────┘
```

- 单向输出，不需要对方安装拼图
- 多种卡片样式可选
- 底部带产品水印，自然完成传播

#### 5.2 亲密空间

面向最亲密的人的小圈子，不超过 5 人：

**适用场景**：
- 情侣：共同记录恋爱点滴，双方都能看到和补充
- 家庭：孩子的成长记录，爸妈爷奶都能看到
- 闺蜜/死党：旅行记录共建

**设计原则**：
- 不叫"好友"，叫"家人"或"搭档"
- 没有点赞，没有评论区，只有"拥抱"这样轻量的温暖反馈
- 用户主动选择哪些记录共享到亲密空间，**默认不共享**
- 亲密空间内的记录不影响个人画像数据

#### 5.3 时间胶囊

写给未来的自己或特定的人，设定日期后密封：

```
┌───────────────────────────────┐
│  🔒 时间胶囊                   │
│                               │
│  收件人：[自己 / 选择联系人]    │
│  解封日期：[选择日期]           │
│                               │
│  ┌───────────────────────┐    │
│  │ 写点什么吧...          │    │
│  └───────────────────────┘    │
│                               │
│  📎 可附上照片或语音           │
│                               │
│  密封后不可查看，到期自动解封    │
│  [密封胶囊 🔐]                 │
└───────────────────────────────┘
```

- 密封后在到期前不可查看，强化仪式感
- 到期当天推送解封通知，情感冲击极强
- 可以写给自己、家人、朋友
- "给一年后的自己写封信"本身具有社交媒体话题性

### 6 关系哲学：深刻理解，但不做社交

#### 6.1 为什么"我的关系"是核心维度

"人是社会关系的总和。"一个完全不考虑关系的"围绕我"的产品，是不完整的。

但拼图理解关系的方式，和社交产品完全不同：

```
社交产品：连接人与人 → 促进互动 → 关系是目的
拼图：    记录我的关系 → 分析关系中的我 → 关系是认识自己的镜子
```

拼图不帮你维护关系、拓展人脉、认识新朋友。它做的是：**让你看见自己在关系中的样子。**

- 谁是让你真正放松的人？
- 你的社交模式是在变深还是变浅？
- 你在关系中是倾听者还是主导者？
- 哪些关系在给你充电，哪些在消耗你？
- 你有没有正在忽视某个重要的人？

这些问题的答案不需要社交功能，只需要用户自己的记录和 AI 的分析。

#### 6.2 拼图对"关系"做什么和不做什么

**做的事——用关系照见自己**：

| 做 | 说明 |
|------|------|
| 人物档案 | 记录对"我"重要的人的信息、故事、共同经历 |
| 关系洞察 | AI 分析"我"和不同人相处时的情绪、频率、变化 |
| 社交能量分析 | 理解什么样的社交让"我"充电，什么让"我"消耗 |
| 关系变迁追踪 | 看见"我"的关系圈如何随时间演变 |
| 关系中的"我" | 揭示"我"在不同关系中扮演的角色和行为模式 |
| 关系提醒 | "你已经 3 个月没提到爷爷了"——提醒"我"别忽视重要的人 |

**不做的事——不做社交产品**：

| 不做 | 原因 |
|------|------|
| 公开主页 / 个人页 | 不是社交产品，不需要展示自己 |
| 关注 / 粉丝体系 | 会引入社交压力和比较心理 |
| 发现页 / 推荐流 | 不需要内容分发，用户只看自己的 |
| 公开点赞数 / 评论区 | 会导致为了数据好看而表演式记录 |
| 陌生人社交 | 与产品定位完全冲突 |
| 内容审核体系 | 没有公开内容，不需要审核 |

#### 6.3 为什么坚持不做社交

社交属性和拼图的核心价值存在根本矛盾：

- **写给别人看 vs 写给自己看**：一旦有社交压力，用户会自我审查，不会记录真实的情绪、体重、焦虑。数据变成表演，不是记忆。
- **数据真实性**：AI 对话、个人画像、关系分析都依赖真实数据。如果用户因为社交压力美化自己的记录，一切功能失去意义——包括关系画像本身。
- **差异化**：市场不缺社交产品（朋友圈、Instagram、小红书），但缺一个"只为自己记录的私人空间"。拼图对关系的深度理解能力，恰恰建立在"没有社交压力所以数据真实"这个基础上。

**深刻理解关系，但不做社交产品——这不是矛盾，而是拼图独特的立场。**

### 7 隐私与安全

作为一个存储用户最私密信息的产品，信任是一切的基础：

| 功能 | 说明 |
|------|------|
| 默认私密 | 所有记录默认仅自己可见 |
| 生物识别锁 | Face ID / 指纹进入 APP |
| 数据加密 | 敏感内容端到端加密 |
| 数据导出 | 随时导出所有个人数据（JSON / PDF / Markdown） |
| 数据删除 | 删除账号时彻底清除所有数据 |

### 9 如果只能做四个功能就上线

```
1. 极简记录    →  把我的碎片留下来
2. 那年今日    →  让过去的我回来找我
3. AI 对话记忆  →  和我的数据对话
4. 认识自己    →  看见完整的我
```

这四个功能围绕"我"形成完整闭环：

```
我的碎片越多 → 我的回忆越丰富 → AI 越懂我 → 我越了解自己 → 我越想继续记录
```

**拼图的终极护城河不是功能，是"我"本身。** 用户在拼图里积累的不只是数据，而是一个越来越完整的"数字化的我"。这个"我"无法迁移到其他产品——碎片越多，拼图越完整，用户越不可能离开。

**关于我的一切，都在这里。这就是拼图。**
