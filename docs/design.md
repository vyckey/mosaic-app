# 拼图 (Mosaic) - 产品设计文档

## 一、出发点

### 1.1 核心哲学：围绕"我"

**拼图只有一个中心——"我"。**

不是一个记录工具，不是一个日记本，不是一个数据仓库。拼图是**关于"我"的一切的产品**。我的情绪、我的身体、我的关系、我的成长、我的每一天——所有关于"我"的碎片，都汇聚在这里，最终拼出一个完整的"我"。

```
关于我的一切，都在这里。
```

### 1.2 要解决的问题

人对自己的了解，远不如自己以为的那么多。

- "我最近过得怎么样？" —— 说不清。
- "什么事让我真正开心？" —— 凭感觉。
- "我和身边的人，关系在变近还是变远？" —— 没留意过。
- "我这几年变了吗？" —— 模糊的印象。
- "我到底是一个什么样的人？" —— 答不上来。

原因很简单：**关于"我"的数据散落在各处，而且大部分已经丢失了。**

情绪没有记下来，就忘了。想法没有写下来，就没了。经历没有留下来，就模糊了。没有数据，就没有认知。

拼图要做的事：**让"我"的每一块碎片都不再丢失，然后帮"我"把这些碎片拼成一幅完整的画。**

具体要解决三个障碍：

**记录太麻烦** —— 打开APP、选分类、填表单、写长文……每多一步都在劝退。拼图的目标是 10 秒完成一次记录，一句话就是一块拼图。

**记了也白记** —— 日记写了锁在那里，照片拍了沉在相册底部。记录的价值不在写的那一刻，而在未来某天重新看到时。拼图让碎片主动"回来找你"。

**看不见全貌** —— 碎片再多，散着也没用。拼图用 AI 把碎片连起来，让你看见自己的规律、变化和全貌。

### 1.3 产品定位

```
拼图 —— 拼出完整的我

关于我的一切，都在这里。
```

拼图不是社交网络，不是内容平台，不是又一个朋友圈。它是一个**完全围绕"我"的私人产品**。用户在这里不需要表演，不需要迎合，只需要真实地做自己。每一条记录都是一块碎片，日积月累，这些碎片拼出一幅完整的"我"。

### 1.4 产品价值链

```
                         ┌───────┐
                         │   我   │
                         └───┬───┘
                             │
        ┌──────────┬─────────┼─────────┬──────────┐
        │          │         │         │          │
  ┌─────▼─────┐┌───▼───┐┌───▼────┐┌───▼────────┐
  │  记录碎片  ││回顾碎片││ AI 对话 ││  认识自己   │
  │（留下我） ││（我回来）││（懂我） ││（看见完整的我）│
  └─────┬─────┘└───┬───┘└───┬────┘└───┬────────┘
        │          │         │         │
        └──────────┴─────────┼─────────┘
                             │
                    碎片越多，我越完整
                    越完整，越想继续记录
```

## 三、核心功能

所有核心功能围绕一个中心展开：**"我"**。每个功能都是在帮用户回答关于"我"的某个问题。

```
我想记住这一刻（极简记录）→ 过去的我回来了（那年今日）→ 懂我、让我看见自己（AI 对话）
```

### 3.1 极简记录 —— 把我的碎片留下来

**解决的问题**：降低记录门槛，让记录这件事不再是负担。

**设计原则**：任何一次记录，不超过 10 秒能完成。

**核心交互**：不按品类分散入口，而是一个统一输入框解决所有类型。用户只管用自然语言输入，AI 自动识别类型并结构化。

```
输入："今天跑了5公里 感觉不错"
AI 识别 → 运动记录，距离: 5km，情绪: 积极

输入："体重72.5"
AI 识别 → 健康数据，体重: 72.5kg，更新体重曲线

输入："读完了三体 震撼 9分"
AI 识别 → 阅读记录，书名: 三体，评分: 9，状态: 已读完

输入："和妈妈吃了火锅"
AI 识别 → 美食 + 人际记录，关联人物"妈妈"
```

用户也可以手动修正 AI 的分类，AI 从修正中学习，越用越准。

**多种速记方式**：

| 方式 | 场景 | 说明 |
|------|------|------|
| 打字 | 最通用 | 一句话即可完成一条记录 |
| 拍照 + 一句话 | 吃饭、风景、到达某地 | 拍照后自动识别场景生成描述草稿 |
| 语音 | 走路、开车 | 按住说话，AI 转文字并提取结构化信息 |
| Emoji 选择 | 快速心情打卡 | 点一个 Emoji 就是一条记录，零门槛 |
| Widget | 桌面 | 不用打开 APP，桌面小组件一键记录 |
| Apple Watch | 手腕 | 抬手快速语音记录或心情打卡 |
| 转发导入 | 从其他 APP | 从微信/相册/其他 APP 分享内容到拼图 |

### 3.2 那年今日 —— 让记忆主动回来找你

**解决的问题**：让用户感受到"记录是有价值的"，驱动持续记录。

**为什么是核心功能**：Facebook 和 Apple Photos 已经验证了这个功能的情感威力。用户为了未来能收到这样的回忆推送，愿意现在开始记录。这个功能是让用户理解产品价值的最快方式：你记录的东西，未来会以一种温暖的方式回来找你。

**功能设计**：

- 每天推送历史上的今天记录了什么，不只是一年前，是所有年份的今天
- 碎片越多，这个功能越有价值，形成正向循环
- 推送时间可自定义（默认早上 9:00，用温暖的回忆开启新的一天）

**冷启动策略**（新用户没有历史数据时）：

- 引导用户导入相册照片，按日期自动生成历史记录骨架
- 引导用户补录几个重要人生节点（毕业、第一份工作、重要旅行等）
- 第一条回忆推送到来时，用户会产生强烈的"还好我记了"的感受

**延伸功能**：

| 功能 | 说明 |
|------|------|
| 记忆惊喜 | 随机时间推送一条旧记录，类似开盲盒 |
| 关联推送 | 今天记了"下雨了"，推送以前下雨天的记录 |
| 地点触发 | 到达某个去过的地方，推送上次在这里的记录 |

### 3.3 AI 对话 —— 和自己的数据对话，和 AI 聊"我是谁"

**解决的问题**：让积累的数据真正"活"起来——既能帮用户查找和分析自己的记录，又能帮用户从碎片中看到完整的自己。

**产品位置**：统一在底部"对话" Tab 中。用户不需要区分"查数据"还是"聊自己"，在同一个对话框里自然切换——问"上次吃火锅是什么时候"和问"我是一个什么样的人"，发生在同一个界面。

**为什么是核心功能**：

- **差异化护城河**：不是通用 AI 聊天，而是基于用户自己的数据回答关于自己的问题。没有其他 APP 能做到这一点，因为只有拼图积累了这些数据。数据越多，AI 越懂你，越难离开。
- **自我认知的独特价值**：人很难客观认识自己，判断往往基于最近的情绪和模糊印象。拼图拥有长期真实数据——每一次开心、低落、决定、关系变化。AI 能提炼出用户自己都没意识到的规律和真相。

#### 3.3.1 产品形态

AI 对话的能力分布在两个 Tab 中：

- **"对话" Tab**：承载所有对话式交互——数据查询、自由提问、话题探索、AI 引导式对话
- **"我" Tab**：承载非对话式的自我认知——我的画像、关系画像、仪表盘、人生故事、探索话题入口

**"我" Tab 页面内容**：我的画像摘要 → AI 新发现卡片 → 探索话题入口（我的性格 / 我的关系 / 我的成长 / 情绪规律 / 人生阶段 / 价值观）→ 个人仪表盘入口 → 设置。点击探索话题或"展开聊聊"会跳转到"对话" Tab，进入对应的对话上下文。

> 页面设计详见 [memory-product-detail.md](memory-product-detail.md) 第 1 章、第 4 章。

#### 3.3.2 AI 能力谱

从浅到深，AI 对话覆盖四个能力层次：

```
记忆检索（帮我查）→ 数据分析（帮我算）→ 自我探索（帮我理解）→ 主动洞察（不问也告诉我）
```

**层次一：记忆检索 —— "帮我查"**

| 能力 | 示例 |
|------|------|
| 事实检索 | "上次和妈妈吃火锅是什么时候" |
| 时间段总结 | "我上个月/上半年/去年过得怎么样" |
| 人际查询 | "我和小明一共见过几次面" |

```
用户：我和小明的友谊是怎样的？

拼图 AI：你和小明从 2024 年 3 月开始出现在你的记录里。
到现在一共提到了 47 次。你们一起去过 3 个城市旅行，
每个月平均见 2 次面。你和他相关的记录情绪均值是 8.7，
是你所有社交记录中最高的。
上次见面是 8 月 15 日，你们一起去了一家新开的居酒屋。
```

**层次二：数据分析 —— "帮我算"**

| 能力 | 示例 |
|------|------|
| 趋势分析 | "我的运动习惯有什么变化" |
| 情绪洞察 | "什么让我开心/焦虑" |
| 习惯发现 | "我有什么规律性的行为模式" |
| 趋势预警 | "你已经连续 7 天没运动了" |

```
用户：什么事情能让我开心？

拼图 AI：根据你过去一年的记录分析，
让你情绪评分最高的活动 Top 5：
1. 和家人聚餐（平均 9.1 分）
2. 户外跑步（平均 8.6 分）
3. 旅行中探索新地方（平均 8.4 分）
4. 读完一本好书（平均 8.2 分）
5. 完成一个工作目标（平均 8.0 分）
```

**层次三：自我探索 —— "帮我理解我自己"**

这是拼图 AI 和通用 AI 最本质的区别。用户问的不是事实问题，而是关于"我"的哲学问题：

```
用户：我是一个什么样的人？

拼图 AI：根据你 2 年来的 2,847 条记录，我看到的你是这样的：

你是一个重视家庭的人。"妈妈"出现了 156 次，是你记录中最高频的人物。
每次和家人相关的记录，你的情绪评分都在 8 分以上。

你是一个自律但会波动的人。你保持跑步习惯已经 14 个月，但中间有过
两次中断超过 2 周。有意思的是，这两次中断都发生在工作压力最大的时期，
之后你都自己恢复了过来。

你是一个对生活保持好奇的人。你去过 12 个城市，尝试过 8 种不同的运动，
读的书横跨科幻、历史、心理学、商业，没有明显的单一偏好。

你是一个内心丰富但不太外露的人。你的日记比朋友圈记录多 4 倍，
很多深层的想法你选择只留给自己。
```

```
用户：我真正在意的东西是什么？

拼图 AI：从你的记录来看，有几个线索：

你给情绪最高分的时刻不是"成就"而是"连接"——
升职加薪那天你给了 8 分，但和爸妈一起包饺子你给了 9.5 分。

你反复出现的关键词里，"自由"和"掌控感"排名很高。
你情绪最低的记录通常和"被迫做不想做的事"有关。

所以如果让我总结，你在意的排序可能是：
家人 > 自由 > 体验 > 成长 > 物质。

当然，这只是数据呈现的面貌，你觉得准吗？
```

自我探索还包括**话题引导式对话**——用户点击预设话题卡片，AI 围绕主题进行多轮引导：

| 话题 | AI 引导方向 |
|------|------------|
| 我的性格 | 从记录中分析内向/外向、行为模式、决策风格 |
| 我的关系 | 谁对你最重要、关系的变化趋势、社交能量分析 |
| 我的成长 | 技能变化、认知变化、从复盘记录中提取成长轨迹 |
| 情绪规律 | 情绪周期、触发因素、季节性波动、应对模式 |
| 人生阶段 | AI 识别出的人生阶段划分，每个阶段的特征 |
| 价值观 | 从选择和偏好中推导你真正在意的东西 |
| 我的一天 | 你典型的一天是怎样的，工作日和周末的差异 |
| 未来的我 | 基于当前趋势，推测你的发展方向和建议 |

话题探索不是一次性给出结论，而是**多轮对话**，AI 会抛出问题引导用户思考：

```
AI：你的记录显示你在 2025 年 5 月有过一段低潮期，
    那段时间你记录了 "感觉工作没有意义" "每天都在重复"。
    但到了 7 月，你突然开始记录很多新尝试——
    学了潜水、去了云南、读了 3 本心理学的书。

    你还记得那段时间发生了什么让你做出改变吗？

用户：好像是看到一个朋友辞职去旅行了，突然觉得不能这样下去

AI：这很有意思。你的记录里有一个规律——
    每次产生重大改变之前，都有一个"被他人启发"的触发点。
    2024 年你开始跑步，也是因为看到同事跑了马拉松。

    你似乎是一个需要"外部触发"来启动改变的人，
    但一旦启动，你的执行力很强。这是你的模式吗？
```

**层次四：AI 主动洞察 —— 不问也告诉你**

AI 基于数据分析主动生成洞察卡片，出现在"我" Tab 和"今天" Tab 中。洞察示例：

- "你每次旅行回来的第一周，运动频率会翻倍。旅行似乎是你'重新充电'的方式。"
- "过去 3 个月，你提到'累'的频率比之前高了 2 倍，但你的运动和社交频率没有下降。你可能正在透支自己而没有意识到。"

- 洞察卡片不是每天都有，而是 AI 真正发现有价值的规律时才推送
- 用户反馈"觉得准 / 不太对"帮助 AI 校准分析模型
- 点击"展开聊聊"进入对话模式深入探讨这个发现

#### 3.3.3 我的画像

基于所有记录生成的综合性格/生活画像，包含 AI 文字描述 + 特质雷达图 + 数据 MBTI + 六维度画像（情绪/身体/兴趣/生活/关系/成长）。

- 画像不是一次生成永远不变的，而是随着数据积累持续更新
- 用户可以查看画像的变化历史："一年前的你 vs 现在的你"
- 点击"聊聊这个画像"可以进入对话，和 AI 讨论画像的准确性

> 画像页面设计详见 [memory-product-detail.md](memory-product-detail.md) 第 4 章。

#### 3.3.4 我的人生故事

AI 将碎片记录编织成一段连贯的人生叙事，让用户从"第三视角"看自己的经历：

```
用户：帮我回顾下从毕业到现在的经历

拼图 AI：

2023 年 7 月，你大学毕业。那天你记录了"终于结束了，不知道
该开心还是害怕"。这种复杂的情绪在你后来的很多转折点也出现过。

毕业后你去了一家互联网公司做产品经理。最初几个月的记录充满了
新鲜感——"今天学到了好多"、"同事们都很厉害"。但半年后，
"重复"和"无聊"开始出现在你的记录里。

2024 年是你的转折年。3 月份你看到同事跑了马拉松，你记录了
"我也想试试"。从那天起，你开始跑步。一开始 2 公里就上气不接
下气，到年底你跑完了第一个 10 公里。跑步不只是运动——你的
记录显示，开始跑步之后你的情绪稳定性明显提升。

2024 年底你做了一个重要决定：跳槽。从你的记录里能看到这个
决定酝酿了差不多 3 个月...
```

- 不是简单地列出时间线，而是以叙事的方式讲述用户的故事
- 串联因果关系、发现转折点、还原决策过程
- 用户可以指定时间段或主题（"讲讲我的运动故事"、"讲讲我和小明的故事"）

#### 3.3.5 设计原则

| 原则 | 说明 |
|------|------|
| 不是心理咨询 | AI 基于数据给出客观分析，不做诊断和治疗建议 |
| 保持谦逊 | AI 分析完会问"你觉得准吗"，承认数据有局限 |
| 连续谱，非标签 | 不用二元标签定义人，而是展示连续谱上的位置（如"78% 的 I"而非"你是 I"），呈现数据观察到的模式 |
| 数据透明 | 每个结论都可以追溯到具体的记录来源 |
| 用户掌控 | 用户可以标记"这个分析不准"，AI 据此调整 |

## 四、核心产品逻辑

### 4.1 一句话逻辑

**所有功能都是在回答同一个问题："我是谁？"**

记录是在收集"我"的碎片，回顾是在重温"我"的过去，AI 对话是在检索"我"的数据，认识自己是在看见完整的"我"——包括"我"在关系中的样子。人是社会关系的总和，理解"我的关系"是理解"我"不可或缺的维度。产品的一切围绕"我"展开，"我"是唯一的中心。

### 4.2 正向飞轮

```
碎片越多 → "我"越完整 → 越能看见自己 → 越想继续记录
    │                                        │
    └────────────────────────────────────────┘
```

展开来看：

```
我记下一块碎片（极简记录）
    ↓
过去的碎片回来找我（那年今日）→ "还好我记了"
    ↓
我和自己的数据对话、看见完整的自己（AI 对话）→ "原来我是这样的"
    ↓
"我想继续记录" → 回到第一步，碎片更多，画面更清晰
```

### 4.3 三个核心功能如何围绕"我"

```
                    ┌───────────┐
                    │     我     │
                    └─────┬─────┘
                          │
        ┌─────────────────┼─────────────────┐
        │                 │                 │
   ┌────▼───┐       ┌────▼────┐       ┌────▼────┐
   │ 极简记录│       │ 那年今日 │       │ AI 对话  │
   └────┬───┘       └────┬────┘       └────┬────┘
        │                │                 │
   把我留下来         让我回来        懂我、让我看见自己
```

| 模块 | 围绕"我"解决什么 | 用户心声 |
|------|-----------------|---------|
| 极简记录 | 把"我"的碎片留下来 | "我想记住这一刻" |
| 那年今日 | 让过去的"我"回来 | "原来那天的我是这样的" |
| AI 对话 | 帮"我"检索数据、理解自己、看见完整的自己 | "我上次是什么时候？""我到底是什么样的人？" |

**拼图的终极护城河不是功能，是"我"本身。** 用户在拼图里积累的不只是数据，而是一个越来越完整的"数字化的我"。这个"我"无法迁移到其他产品——碎片越多，拼图越完整，用户越不可能离开。

**关于我的一切，都在这里。这就是拼图。**
